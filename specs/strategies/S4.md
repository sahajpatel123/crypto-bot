# S4 failed-breakout reclaim reversal — exact rules v0.1.0 (Worker 1, Q-004)

Status: BASELINE (simulation only; not a validated trading system).
Directive Sec 5 hypothesis: a shallow breakout pierce that is reclaimed
within a few bars traps momentum chasers; enter the reversal toward the
range interior. Replaces the Q-002 unimplemented S4 SPEC. No
hidden-liquidity claims: the signal is price reclaim + momentum only.
Contract: v0.2.0 (Intent schema unchanged). All replay inputs are synthetic
and labelled (`source: "synthetic"`).

## 1. Bar schema and causality

Same 1-second bar schema as S1/S2. Evaluate at bar index `t`;
`evidence_ts_utc` = `bars[t].ts_utc`. The reference level excludes the
pierce lookback (so pierce bars cannot absorb the level); reclaim and
momentum use bars ending at `t`. Minimum history `t >= 120` (shared
replay warmup). Smaller `t` yields no evaluation (`history=fail`).

## 4. Per-side rules (long and short evaluated separately)

### 4.1 SHORT fade of a failed upside breakout (all must hold)

1. Level: `H = max(high[t-120..t-7])`.
2. Pierce (S4 only): `P = max(high[t-6..t-1]) > H` (strict) and
   `(P−H)/H·10⁴ <= 6.0` (shallow pierce only).
3. Reclaim: `close[t] < H` (strict) and
   `close[t] < min(close[t-5..t-1])` (strict).
4. Reversal momentum: `(close[t]/close[t-10] − 1)·10⁴ <= −4.0` bps.
5. Spread: `spread_bps[t] <= 3.0`.

No-trade conditions: no level pierce in the lookback (for S4), deep
pierce beyond 6 bps (true breakout, not a failure), no reclaim print
(price still outside), weak reversal momentum, wide spread, any gap in
`t-120..t`.

### 4.2 LONG fade of a failed downside breakdown (mirror)

1. Level: `L = min(low[t-120..t-7])`.
2. Pierce (S4 only): `P = min(low[t-6..t-1]) < L` (strict) and
   `(L−P)/L·10⁴ <= 6.0`.
3. Reclaim: `close[t] > L` (strict) and
   `close[t] > max(close[t-5..t-1])` (strict).
4. `(close[t]/close[t-10] − 1)·10⁴ >= +4.0` bps.
5. Same spread gate.

### 4.3 Reject checks (in order, every outcome recorded)

`history`, `gap` (window `t-120..t`; halt/degraded; never emit on gaps),
`spread`, `pierce`, `reclaim`, `momentum`, `bounds`. All gates evaluated
independently; fire requires every applicable gate to pass.

Regime labels: `failed-breakout-short` / `failed-breakout-long` on fire,
else `no-setup`. Trigger strings: `pierce(6)+reclaim(5)+momentum(10)`
(S4) or `reclaim(5)+momentum(10)` (S4-S); `no-fire` otherwise.

## 5. Intent construction on fire

- `strategy` = arm id; `version = "0.1.0"`; side = evaluated side.
- SHORT: `entry_high = close[t]`, `entry_low = close[t]·(1−2bps)`,
  `invalidation = max(high[t-6..t])·(1+2bps)`. Ordering proof: the max
  covers the trigger bar's own high, so it is `>= close[t]`, and the
  `+2bps` buffer makes invalidation strictly above `entry_high` whenever
  prices are positive — including the S4-S arm without a pierce.
- LONG: `entry_low = close[t]`, `entry_high = close[t]·(1+2bps)`,
  `invalidation = min(low[t-6..t])·(1−2bps)` (mirror proof).
- `entry_expiry_utc = evidence + 15s`; `holding_limit_s = 120`;
  `exit_rule`, `forecast_cost` from §2; `data_quality = clean`
  (`no-gaps-N=120`); `evidence_ref` = deterministic record id.
- The paired `DecisionRecord` carries regime, one `FeatureEvidence` per
  evaluated feature, the trigger clause, all reject outcomes, and the
  data-quality state. No confidence percentages.
