# S2 trend-pullback continuation — exact rules v0.1.0 (Worker 1, Q-002)

Status: BASELINE (simulation only; not a validated trading system).
D-010 correction: this spec implements the directive's S2 hypothesis
(trend pullback continuation), replacing the Q-001 range-fade draft.
Contract: CONTRACTS.md v0.1.1 (Intent schema unchanged from v0.1.0).
Strategy-side builders reuse manager-owned `cryptobot.coordination`.
All replay inputs are synthetic and labelled (`source: "synthetic"`).

## 1. Bar schema and causality

Same 1-second bar schema as S1 (see `specs/strategies/S1.md` §1):
`ts_utc`, `open/high/low/close`, `volume`, `trades`, `buy_frac`,
`spread_bps`, `source`. Missing bars are explicit `None`.

Evaluate at bar index `t`; `evidence_ts_utc` = `bars[t].ts_utc`. The setup
(trend, swing, pullback) is measured over bars ending at `t-1`, so the full
setup is known before the trigger bar; the trigger uses bar `t`'s own
fields, causal at its close. Minimum history `t >= 120` (shared replay
warmup with S1). Smaller `t` yields no evaluation
(`history=fail`, reason `insufficient-history`).

## 3. Arms (bounded alternatives for EXP-002)

- `S2` — pullback + resumption alone.
- `S2-V` — plus volume confirmation (`vol_z >= 1.0`).
- `S2-F` — plus order-flow confirmation (mean directional fraction `>= 0.58`).

All arms share version `0.1.0` and differ ONLY by the confirmation gate.

## 4. Per-side rules (long and short evaluated separately)

### 4.1 LONG (all must hold)

Setup (bars ending `t-1`):
1. Swing high `H = max(high[t-60..t-1])`, first index `H_idx`; sequence
   gate: `H_idx <= t-11` (high made before the pullback window).
2. Swing trend `(H/close[t-61] − 1)·10⁴ >= 25.0` bps (trend measured to
   the swing extreme, so the pullback itself cannot erase it).
3. Pullback low `L = min(low[t-10..t-1])`;
   `depth = (H−L)/H·10⁴` within `[8.0, 60.0]` bps.

Trigger (bar `t`):
4. `close[t] > max(close[t-5..t-1])` (strict resumption).
5. `(close[t]/close[t-5] − 1)·10⁴ >= 2.0` bps.
6. Arm gate (§3; `S2-V`: z rule identical to S1; `S2-F`: mean buy
   fraction over `t-9..t >= 0.58`).

### 4.2 SHORT (mirror)

1. Swing low `S = min(low[t-60..t-1])`, first index `S_idx <= t-11`.
2. Swing trend `(S/close[t-61] − 1)·10⁴ <= −25.0` bps.
3. Pullback high `P = max(high[t-10..t-1])`;
   `depth = (P−S)/S·10⁴` within `[8.0, 60.0]`.
4. `close[t] < min(close[t-5..t-1])` (strict).
5. `(close[t]/close[t-5] − 1)·10⁴ <= −2.0` bps.
6. Arm gate (`S2-F` uses mean sell fraction `1 − buy_frac`).

### 4.3 Reject checks (in order, every outcome recorded)

`history`, `gap` (window `t-120..t`; halt if consecutive-missing `> 5` or
any timestamp disorder, else degraded; never emit on gapped windows),
`spread`, `sequence`, `trend`, `pullback`, `resume`, `momentum`,
`confirm` (`na(S2)` on the base arm), `bounds`. All gates are evaluated
independently (no short-circuit); fire requires every gate to pass.

Regime labels: `pullback-long` / `pullback-short` on fire, else `no-setup`.
Trigger strings: `trend(60)+pullback(10)+resume(5)` plus `+volz(60)` /
`+flow(10)` on confirming arms; `no-fire` otherwise.

## 5. Intent construction on fire

- `strategy` = arm id; `version = "0.1.0"`; side = evaluated side.
- LONG: `entry_low = close[t]`, `entry_high = close[t]·(1+2bps)`,
  `invalidation = L·(1−2bps)`. Ordering proof: the resume gate gives
  `close[t] > max(close[t-5..t-1]) >= close[t-1] >= low[t-1] >= L`, so
  `invalidation < L < entry_low` strictly whenever the trigger holds.
- SHORT: `entry_high = close[t]`, `entry_low = close[t]·(1−2bps)`,
  `invalidation = P·(1+2bps)` (mirror proof).
- `entry_expiry_utc = evidence + 15s`; `holding_limit_s = 120`;
  `exit_rule`, `forecast_cost` from §2; `data_quality = clean`
  (`no-gaps-N=120`); `evidence_ref` = deterministic record id
  (same `{strategy}:{version}:{instrument}:{side}:{iso}` format as S1).
- The paired `DecisionRecord` carries regime, one `FeatureEvidence` per
  evaluated feature, the trigger clause, all reject outcomes, and the
  data-quality state. No confidence percentages.
