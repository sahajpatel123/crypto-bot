# S1 breakout-momentum — exact rules v0.1.0 (Worker 1, Q-001)

Status: BASELINE (simulation only; not a validated trading system).
Contract: CONTRACTS.md v0.1.0. Strategy-side builders in
`src/cryptobot/strategies/contract.py` reuse the manager-owned
`cryptobot.coordination` classes (no duplicate Intent type).
All replay inputs here are synthetic and labelled (`source: "synthetic"`).

## 1. Bar schema (1-second replay bars)

Each bar: `ts_utc` (tz-aware UTC datetime, 1s grid), `open/high/low/close`
(float, `high >= low`, all finite, `close > 0`), `volume` (float `>= 0`),
`trades` (int `>= 0`), `buy_frac` (float in `[0, 1]`, synthetic order-flow
proxy: fraction of bar volume marked buyer-initiated), `spread_bps`
(float `>= 0`, synthetic touched spread), `source = "synthetic"`.
Missing bars are explicit `None` placeholders (never silently dropped).

## 2. Evaluation point and causality

Evaluate at bar index `t` (`0`-based). `evidence_ts_utc` = `bars[t].ts_utc`.
Every window below ends at `t` or `t-1`: no observation with timestamp
later than `evidence_ts_utc` may influence the decision. Reference and
invalidation windows EXCLUDE bar `t`; the trigger bar's own fields
(`close[t]`, `volume[t]`, `buy_frac[t]`, `spread_bps[t]`) are causal because
they are known at the bar close that defines `evidence_ts_utc`.

Minimum history: `t >= 120`. Smaller `t` yields no evaluation
(`history=fail`, reason `insufficient-history`), never a partial window.

## 3. Frozen parameters v0.1.0

| Name | Value | Meaning |
|---|---|---|
| `BREAKOUT_N` | 120 | reference window: bars `t-120..t-1` |
| `MOM_M` | 30 | momentum lookback in bars |
| `MOM_MIN_BPS` | 5.0 | min \|30-bar return\| in bps |
| `VOL_V` | 60 | volume baseline: bars `t-60..t-1` |
| `VOL_Z_MIN` | 1.0 | min volume z-score (S1-V only) |
| `FLOW_F` | 10 | flow window: bars `t-9..t` inclusive |
| `FLOW_MIN` | 0.58 | min mean directional fraction (S1-F only) |
| `SPREAD_MAX_BPS` | 3.0 | reject if `spread_bps[t]` above |
| `ENTRY_TOL_BPS` | 2.0 | entry-bound width from trigger close |
| `ENTRY_EXPIRY_S` | 15 | `entry_expiry_utc = evidence + 15s` |
| `HOLDING_LIMIT_S` | 120 | inside contract range 30–300 |
| `INVAL_M` | 30 | swing window: bars `t-30..t-1` |
| `HALT_GAP` | 5 | consecutive missing bars `> 5` → halt |

Exit rule: `S1_EXIT_V1:take_r=1.5,stop_r=1.0`, where `R = |entry_ref − inval|`
with `entry_ref = close[t]` (target `1.5R`, stop `1.0R`, plus the
`HOLDING_LIMIT_S` time stop; all exits owned downstream per coordinator rules).

Forecast cost (all arms, per-side estimates, labelled
`conservative-simulation`, every leg non-zero):
`fee_bps=5.0, spread_bps=5.0, slippage_bps=5.0, funding_bps=1.0`.
Net-economics method `NET_S1_V1` (see `specs/strategies/EXP-001.md`):
round-trip estimate `= 2·(fee+slippage) + spread + funding`, all in bps.

## 4. Arms (bounded alternatives for EXP-001)

- `S1` — breakout alone (no confirmation gate).
- `S1-V` — breakout + volume confirmation (`vol_z >= 1.0`).
- `S1-F` — breakout + order-flow confirmation (mean directional
  fraction over 10 bars `>= 0.58`).

All arms share version `0.1.0`, windows, thresholds, costs, and exit rule;
they differ ONLY by the confirmation gate. No other variants exist in v0.1.0.

## 5. Per-side rules (long and short evaluated separately)

Each side is an independent evaluation with its own evidence. Both sides are
evaluated for every eligible bar; opposing simultaneous fires are passed
downstream (coordinator stands aside per contract).

### 5.1 LONG trigger (all must hold)

1. `close[t] > max(high[t-120..t-1])` (strict).
2. `momentum = (close[t]/close[t-30] − 1)·10⁴ >= 5.0` bps.
3. Arm gate: `S1`: none; `S1-V`: `vol_z >= 1.0` where
   `vol_z = (volume[t] − mean)/pstdev` over `volume[t-60..t-1]`
   (population std; if `std < 1e-9`: `z = 0.0` when `volume[t] <= mean`,
   else `+inf`); `S1-F`: `mean(buy_frac[t-9..t]) >= 0.58`.

### 5.2 SHORT trigger (mirror)

1. `close[t] < min(low[t-120..t-1])` (strict).
2. `(close[t]/close[t-30] − 1)·10⁴ <= −5.0` bps.
3. Arm gate: `S1`: none; `S1-V`: same `vol_z >= 1.0`; `S1-F`:
   `mean(1 − buy_frac[t-9..t]) >= 0.58`.

### 5.3 Reject checks (evaluated in order, every outcome recorded)

1. `history`: `t >= 120`, else fail `insufficient-history`.
2. `gap`: any `None` in bars `t-120..t`, or any step `!= 1s` in
   `ts_utc[t-119..t]`, fails. Consecutive-missing `> 5` (or any timestamp
   disorder) → `data_quality = halt`; otherwise `degraded`. No intent is
   ever emitted on a gapped window.
3. `spread`: `spread_bps[t] > 3.0` fails.
4. `breakout`, `momentum`, `confirm`: per §5.1/§5.2 (`confirm=na(S1)` on
   the base arm).
5. `bounds`: structural post-check (entry ordering, invalidation side).

Regime labels: `breakout-long` / `breakout-short` on fire, else
`no-breakout`. Trigger strings: `close>donchian_high(120)+momentum(30)`
plus `+volz(60)` / `+flow(10)` on confirming arms (short side mirrors with
`<` and `donchian_low`); `no-fire` when nothing fires.

## 6. Intent construction on fire

- `strategy` = arm id; `version = "0.1.0"`; `instrument` from the replay
  fixture (e.g. `BTCUSDT`); `side` = evaluated side.
- LONG: `entry_low = close[t]`, `entry_high = close[t]·(1+2bps)`,
  `invalidation = min(low[t-30..t-1])` (strictly below `entry_low` whenever
  the §5.1 trigger holds, since `close[t]` exceeds all prior highs).
- SHORT: `entry_high = close[t]`, `entry_low = close[t]·(1−2bps)`,
  `invalidation = max(high[t-30..t-1])` (strictly above `entry_high`).
- `entry_expiry_utc = evidence_ts_utc + 15s`; `holding_limit_s = 120`;
  `exit_rule`, `forecast_cost` from §3; `data_quality = clean` with reason
  `no-gaps-N=120` (only clean windows reach this step).
- `evidence_ref = record_id = "{strategy}:{version}:{instrument}:{side}:{iso}"`
  with `{iso} = evidence_ts_utc.isoformat()`; deterministic, no randomness.
- The paired `DecisionRecord` carries regime, one `FeatureEvidence` per
  evaluated feature (name, window, threshold, observed value), the trigger
  clause, all reject-check outcomes, and the data-quality state. No
  confidence percentages anywhere.
