  commands, timestamps, and data-quality notes. Never mix synthetic and observed.

header; every synthetic recording is labelled `synthetic`. The replayer
(`tools/replay_public.py --expect-class`) enforces the label at the boundary.

## Data-quality notes

- REST backfill vs streaming staleness: a closed candle observed long after
  its close is flagged stale by construction (59/59 in the sample, max lag
  ~58min). For backfill this number measures history age, not feed health;
  the 30s threshold is meaningful for streaming/event capture. Interpret
  accordingly; use `--stale-after-ms` for the capture mode at hand.
- The last REST kline row is normally the still-forming candle. The recorder
  derives `closed` from timestamps (close <= receipt) instead of assuming all
  REST rows closed; the replayer excludes forming candles from gap/stale stats.
- Gap detection assumes an exact interval grid on exchange open time; any venue
  maintenance gap would surface as a `GapRange` in the footer stats.
- Public REST only; no credentials were used or needed. Nominal public-endpoint
  latency observed: ~0.9-2.7s per request from this host.
