## Protocol for any future claim

`cryptobot verdict` emits PASS/FAIL/UNDERPOWERED bound to config, data
and code hashes. PASS requires: bootstrap CI95 lower bound > 0 at
realistic cost, expectancy > 0 at 2x adverse cost, ≥300 trades, ≥60%
non-negative days, drawdown inside budget, and Holm correction across
the six-hypothesis family (H1–H6). Confirmation is exactly once per
hypothesis, only through a sealed vault chunk and a one-shot token.
Too few trades is UNDERPOWERED and stays in AWAIT_CONFIRM_DATA; the
same window is never re-run.

## What happens next (no owner prompt needed)

The recorder accrues public data; `cryptobot autopilot run-once` moves
each hypothesis through REGISTERED → DEV_EVAL → … and writes a daily
report. A failed hypothesis is KILLED permanently. A PASS starts a
14-day pessimistic paper run; only PAPER_COMPARE success produces
GATE_READY, which is one input to the human-only gate/arm ceremony.
